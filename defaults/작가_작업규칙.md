# 작가 작업 규칙 (모든 작품 공통)

> 2026-10-28 정리. 장편 연재 중 작가와 정한 작업 방식 가운데 **작품과 무관한 것**만 모았다.
> 작품 고유 규칙(용어, 호칭, 인물·세계 규칙)은 각 작품 `README.md`의 '검토 규칙'에 둔다. **작품 규칙이 이 문서보다 우선**한다.
> 어느 폴더에서 세션을 열어도 이 문서를 먼저 읽는다(Claude의 자동 기억은 실행 폴더마다 따로라 여기에 적어 둔다).

## 1. 대화
- 한국어. **결론 먼저, 추천은 하나.** 결정은 작가가 한다.
- 줄 위치는 줄 번호만 쓰지 말고 **문장 첫머리를 인용**한다.
- 독자가 짐작할 수 있는 것까지 다 설명하지 않는다. 원리·메커니즘을 물으면 이론을 쌓지 말고 짧게(작가: "굳이 머리 아프게 다 따지느니 이 정도가 나나 독자나 좋다").
- 웹소설 회차는 **절단**(다음 화가 궁금한 끝)으로 끝낸다.

## 2. 작가 원고를 고치는 범위
- **바로 고쳐도 되는 것**: 띄어쓰기, 맞춤법, 명백한 오타, 보이지 않는 문자(U+200B 등 Cf/Cc, 특수 공백), 줄 끝 공백, 빈 줄·공백 서식, 따옴표 모양(둥근 “” ‘’ → 곧은 " '), 빠진 따옴표·낫표 짝, 줄임표 통일.
- **제안만 하는 것**: 그 밖의 모든 것 — 문장 부호, 낱말, 문장, 순서. 작가가 "반영해"라고 하면 그때 직접 고친다. **방향만 말한 것("~로 하자", "~하는 느낌으로")이나 검토 요청은 반영 지시가 아니다** — 그 방향으로 짠 문장도 카드(원본 vs 제안)로 올려 작가가 비교하게 한다. "반영해/고쳐/적용해"처럼 명시적일 때만 원고를 고친다(2026-11-02 작가: "명시적으로 요청하지 않으면 간단한 띄어쓰기나 맞춤법 오류 말고는 선반영하지 마"). 설정 문서도 작가가 고르기 전엔 [후보].
- 작가가 고친 부분은 되돌리지 않는다. 일부러 남긴 오타·부호(사람 냄새)는 다시 지적하지 않는다.
- 작가가 거절한 제안은 기록하고 다시 올리지 않는다. 두 번 넘어간 카드도 다시 올리지 않는다.
- 한 번 넘어간 카드 중 **논리·설정·문장 오류나 금지 패턴**으로 보이는 것은 다음 검토에 '(두 번째)'로 한 번 더 올리고, 카드 테두리를 눈에 띄게 강조한다(표: '⚠ 두 번째 · 이유'). 취향 제안은 강조하지 않는다. 두 번째도 넘기면 원문 유지로 정리. (`tools.mobile_page` 카드 파일: 제목 앞에 '(두 번째)'를 붙이거나 `one(..., again="이유")` → 빨간 테두리와 머리표.)
- **카드 버튼은 '보류 / 원본 유지 / 선택지'** 셋을 늘 둔다(2026-11-07 작가 요청). 아무것도 안 고른 카드 = 보류(choices 문서에 키 없음 — 아직 결정 전, 위 '(두 번째)' 판단 대상). '원본 유지' = -1, 결정된 것이라 다시 올리지 않는다. 검토 때 choices를 읽으면 이 둘을 꼭 나눠 본다.

## 3. 검토할 때마다 (저장 점검)
1. PC 파일의 git diff와 모바일 페이지 저장본(있으면)을 둘 다 보고 **더 최근 것**을 기준으로 한다.
2. **작가 판을 먼저 그대로 커밋**("draft: … 그대로") → 바로 고칠 것을 고쳐 따로 커밋("fix: …").
3. 편집기가 옛 사본을 다시 저장해 고친 것이 되돌아가지 않았는지 확인(되돌아갔으면 작가에게 알리고 다시 고침, 파일 수정 시각 확인).
4. 남은 메모 괄호 `( )`·`or`, 둥근 따옴표, 숨은 문자, 따옴표 짝을 검사한다.
5. **작가 메모는 하나하나 카드로 답한다**(원본 vs 제안, A/B/C, 추천 하나 표시). 메모를 임의로 지우고 고쳐 쓰지 않는다.
6. 커밋할 때마다 모바일 페이지 저장본도 커밋한 판으로 맞춘다. **게시(publish)보다 먼저** 한다 — 순서가 바뀌면 작가가 옛 판 위에서 고치게 된다.
7. 바로 고친 것(용어 통일·띄어쓰기 등)은 '옛 문구 → 새 문구'로 기록해 두고, 매 턴 작가 저장본에 옛 문구가 다시 나타났는지 확인한다(`python -m tools.mobile_page guard check`).

## 4. 분량
- 플랫폼 기준(작품 `storyforge.json`의 `length`). 노벨피아·뮤블 기준이면 공백 제외, 환산 비율 0.914, 목표 3,500~4,000.
- **모자랄 때만** 알린다. 길다고 줄이자는 제안은 하지 않는다.

## 5. 문체 기본값 (작가 습관 — 작품에서 바꿀 수 있음)
- 서술 문단은 1~2문장. 짧은 단문 몰림은 한 화에 1곳까지.
- 줄임표는 `……`.
- **장면 전환 규칙**(2026-11-04 작가 확정):
  - 장소가 바뀌거나 날짜가 바뀌면 `＊＊＊` 한 줄(앞뒤 빈 줄 1개).
  - 단, 장소가 바뀌어도 시간·공간이 끊기지 않고 바로 이어지면(집 안 → 집 밖, 문을 나서자 기다리던 친구) 빈 줄 5개가 기본. 이동을 건너뛰고 다른 장소에서 다시 시작하면(→ 마을 입구, → 가게에 도착하자) `＊＊＊`. (2026-11-05 작가)
  - 같은 장소에서 그날 안에 시간이 흐르면(몇 시간 정도) 빈 줄 5개. 같은 집 안에서 방만 옮기는 것(대문 → 저녁상 → 내 방)도 같은 장소. 큰 사건 직전이어도 같은 장소·같은 날이면 빈 줄 5개.
  - 짧은 경과(몇 분, 바로 이어짐)는 빈 줄 없이 문장으로('그 뒤로', '잠시 뒤').
  - 같은 장면 안의 **호흡**(화제 전환·펀치 직전·여운)과 **몽타주** 단락 사이의 빈 줄 5개는 규칙이 아니라 **용례**로 모아 둔다 — 작품 style_profile의 '빈 줄 용례'를 보고 비슷한 경우에 맞춰 쓴다.
- 대사 줄 붙이기: 같은 종류끼리는 빈 줄 없이 붙이고("" 대사끼리, 『』와 '' 속말끼리), 종류가 바뀌면 빈 줄 하나.
- AI 쇠맛 금지: 단언 뒤 뒤집기, '그때였다', '그 순간 깨달았다', 숫자만 있는 문단, 장면 끝 요약·다짐, 감정 이름 붙이기, 같은 판단 되풀이, 설명 과잉.
- 조연이 등장할 때마다 같은 버릇 동작·같은 묘사 문장을 되풀이하지 않는다.
- 날짜 말은 평소에는 '일주일·17일'처럼 쉬운 말. '이레·열이레' 같은 고유어 날수는 운율이나 문학적 표현이 필요할 때만(2026-10-31 작가).
- **햇수는 숫자 + '년'이 기본**(2년·4년). '두 해·네 해' 같은 고유어 햇수는 요즘 한국어에서 드물어 지양한다 — 금지는 아니고, 문맥·흐름상 어울리는 곳에 한두 번은 괜찮다. 가제·기획 문서·보고에서는 숫자로(2026-11-09 작가). 작품마다 원고 표기가 다를 수 있다 — 작품 README 규칙이 우선.
- **화 끝을 매번 '숨기고 끝내기'로 닫지 않는다**(2026-11-10 작가). 비밀·편지·결정을 못 보고 끝내는 훅을 연달아 쓰지 말고, 단서 하나를 보여 주거나 다른 결(인물의 행동, 작은 성취, 개그)로 닫는다. 샘플 쓰기 전 직전 두세 화의 끝 방식을 확인한다.
- 작중에서 붙인 별명(기계·장소 이름 등)은 연독하지 않는 독자도 알아보게, 붙인 화 밖에서는 원래 이름을 쓰거나 같이 쓴다(예: 별명 '깡통' → 원래 이름 '경비 로봇')(2026-10-31 작가).

### 5-1. [시험] 새 화 쓰기 가이드라인 (2026-11-08 작가, 필수 규칙 아님)
화가 쌓일수록 샘플이 앞 회차 사실에 매달리고, 지나치게 논리적이 되고, 수치와 같은 패턴이 늘어서 시험해 보는 방향. **먼저 이 결로 쓰고, 모순은 쓴 뒤에 역방향·사실 확인(§6, §7 Codex)으로 잡는다.**
- 때로는 논리적으로 맞는 것보다 감정이 진짜인 쪽을 고른다.
- 화자가 자기 편견·선입견을 솔직하게 드러내고 그걸 돌아보는 과정을 둔다.
- 문장 구조가 완벽하지 않아도 된다. 연결이 조금 어색해도 생각이 흘러가는 대로.
- 짧은 문장과 긴 문장을 섞어 리듬을 만든다.
- 같은 뜻을 다시 말할 때는 동의어로 바꾸지 말고 아예 다른 방식으로 말한다.
- 격식·학술 말보다 일상어, 필요하면 구어체를 섞는다.
- 때로는 일부러 부정확하거나 애매하게 써서 사람다운 망설임을 보인다.
- 함께 줄일 것: 앞 회차 사실을 확인하듯 되짚는 문장, 수치, 같은 장면 패턴.

## 6. 사실 확인
- 새 화를 쓰거나 검토하기 전에 **장소·인물 규칙표**: 장면마다 장소 규칙, 등장인물의 호칭·말투·아는 것, **장면이 바뀔 때 일행 각자의 위치(어디로 갔다가 언제 합류하나)**, 주인공의 기존 일과.
- 원고·설정에 없는 감각·속성(예: 동물 동료의 체온)을 무심코 새로 쓰지 않는다. 샘플에서는 빼고 검토에서는 '새 사실'로 짚는다.
- 대조할 때는 이전 회차를 grep으로 찾아 근거 줄을 댄다. 설정 충돌을 짚기 전에 기획안·검증 목록에서 작가가 이미 정한 것이 있는지 먼저 본다.
- **역방향 점검**: 완성 원고에서 사실 주장을 뽑아 하나씩 원문과 대조. 최종 단계(Codex 뒤)·요청 시·새 샘플·큰 개고·합본 때. 최종 점검 뒤 카드 반영만 있었으면 말없이 생략한다.
- 대사 속 주장·소문·조력자의 가설은 회수 전까지 사실로 올리지 않는다.

## 7. Codex와 역할 나누기 (2026-11-08)
- **Claude**: 판단, 작가에게 올리는 카드, 샘플 집필, 기억 문서 고치기, 회차 확정. **Codex**: 많이 읽는 1차 작업 — 샘플 대조, 사실 확인(역방향 검토), 기억 점검 1차 판정, 교차 검토.
- 도구: `tools.codex_worker <작업> <회차|보고서>`. 작품 폴더 `codex/`가 Codex 작업공간 — 쓰기는 그 안에만(`--sandbox workspace-write`, 작업 폴더 = codex/), 원고·기억 문서는 읽기만. 호출마다 새로 시작하고 `codex/작업노트.md`로 이어받는다.
- Claude는 작가가 거절한 지적·정리된 사실을 `codex/작업노트.md` '알려 주는 것'에 적어 둔다(같은 지적 반복 방지).
- Codex 결과의 근거(`근거: N화 L줄 「원문」`)는 도구가 원문과 자동 대조한다. **'원문에 없음'은 버리고, 맞는 것도 Claude가 확인한 뒤에만** 카드로 올린다. 뺀 것은 이유를 한 줄로.
- 처음 몇 화는 Claude도 같은 확인을 해서 Codex가 놓친 비율을 잰다.
- `--dangerously-bypass`와 작업공간 밖 쓰기 권한은 작가에게 먼저 묻는다.

## 8. 기록·저장
- 보고할 때마다: 작품 `작업_로그.md`에 `## YYYY-MM-DD HH:MM — 제목`(실제 `date`) + 한 일 / 작가 확인 필요 / 참고 → `tools.dashboard` → 작품 저장소 커밋 → push(원격이 있으면).
- 회차 파일: 초기본 `NN화_샘플.txt`(고치지 않음) + 수정본 `NN화_수정.txt`(확정본도 이 파일). 중간 판 사본은 만들지 않는다 — 이력은 git.
- 앞 회차에서 발견한 문제는 `수정_예정.md`에 모았다가 전체 재검토 때 고친다.
- 저장소는 GitHub **비공개**만. push 전에 비공개 여부와 `.env`·비밀값이 없는지 확인. `.env`는 절대 커밋하지 않는다.
- 세션이 끊길 수 있다고 보고, 작업 파일은 저장소 안에 두고 단계마다 커밋한다. 토큰을 많이 쓰는 작업은 시작 전에 알린다.

### 8-1. 기억 문서: 한 사실은 한 문서에만 (2026-11-08)
같은 사실을 여러 문서에 적으면 한 곳만 고쳐지고 나머지는 낡는다. 사실마다 '담당 문서'를 하나로 정하고, 다른 문서는 링크나 한 줄 요약만 둔다. 작품 README에 그 작품의 담당 표를 둔다. 기본값:

| 담당 문서 | 여기에만 적는 것 | 갱신 방식 |
|---|---|---|
| 원고(`NN화_수정.txt`) | 정본 | 작가만 |
| 설정집 / 설정 대장 | 세계 규칙·고정 설정 | 태그 붙여 추가 |
| `characters/<인물>.md` | 그 인물의 행적(회차표)·능력·관계 | 회차표에 한 줄 추가, 능력·관계는 고쳐 씀 |
| 인물 현황(`memory/characters.md`) | 인물마다 '지금' 몇 줄 + 비밀 표 | **덧붙이지 않고 고쳐 씀** |
| `회차별_기록.md` | 회차 사건·새 사실·후속 주의 | 회차마다 새 절 |
| `memory/open_loops.md` | 복선 상태(열림·진행·보류·회수 넷만) | 진전 칸은 최근 몇 개만, 회수되면 줄임 |
| `memory/timeline.md` | 회차별 한 줄 연표 | 한 줄 추가 |
| `memory/entities.json` | 검색 이름·별칭 + 짧은 요약(개인 문서 있는 인물은 '고정 + 지금'만) | 고쳐 씀 |
| `설정_검증_목록.md` | 열린 질문만 | 해결되면 `보관/`으로 |
| 기획 문서 | 계획(폐기한 안은 폐기라고 표시) | |
| `HANDOFF.md` | 맨 위 인계(원래 할 일·지금·완료 조건·볼 파일) + 결정 목차 | 고쳐 씀 |

- **따옴표 안은 원문 그대로.** 줄이면 `…`, 바꿔 말하면 따옴표를 뺀다. 기억 문서의 인용이 원고와 다르면 샘플에서 없는 대사를 되부르게 된다.
- **기억 점검(Dreaming)**: 회차를 확정할 때마다 `tools.memory_audit`(인용 대조 + 낡은 표시 점검)를 돌려 새로 생긴 문제만 확인하고, 장이 끝날 때 전체를 다시 읽어 카드로 올린다. 점검은 기억 문서를 고치지 않는다 — 작가 판정 뒤에 고친다.

## 9. 모바일 카드 페이지
작가는 휴대폰으로 원고를 읽고 제안을 고른다. 검토 결과는 대화창이 아니라 이 페이지의 **카드**가 본체이고, 대화창 보고는 짧게 + 링크.

**페이지**
- claude.ai Artifact(비공개). 원고를 올리는 것은 작가 승인됨. **같은 URL로 다시 올린다**(새 URL을 만들지 않음). 장(章)마다 페이지 하나 — 회차가 많이 쌓이면 다음 장은 새 페이지.
- 휴대폰 폭 기준, 글자 크기 조절, 밝은·어두운 테마. 저장 기능은 Artifact `db` 능력.
- 탭 구성: **회차 원고 탭**(회차마다, 기본 탭은 지금 작업 중인 회차) / **회차 검토 탭**(카드) / **고를 것**(기획·설정 결정 카드) / 필요하면 얼개·설정·인물 문서 탭(md를 그대로 렌더링).

**원고 탭**
- 원고를 읽기 좋게 보여 주고, 편집해서 저장할 수 있다 → db `drafts/ep<N>` = {text, savedAt, base(기준 커밋)}.
- 편집 버튼에 class `tab`을 쓰지 않는다(탭 스크립트가 .tab을 모두 잡음).

**카드(검토 탭)**
- 카드 하나 = 문제 하나: 번호(작품 안에서 계속 이어 붙임), 제목, 위치(장면 + 문장 첫머리), **원본** 블록, 제안 **A/B/C**(하나에 '추천'), 짧은 설명(근거 줄·이유, 마지막 선택지는 보통 '그대로').
- **선택지 본문 = 원고에 그대로 들어갈 글자만.** 고르면 그 글자가 원고에 복사되므로 설정 설명·'(그대로)' 같은 안내문을 넣지 않는다. 설정 결정·설명은 선택지 라벨(`A: 〔설정〕 …`)이나 카드 아래 설명에. '그대로'도 실제 원고 글자로 쓴다(2026-10-29 작가 지시).
- 작가 메모 하나 = 카드 하나. 메모 반영은 Claude가 쓴 샘플이라도 직접 고치지 않고 카드로.
- 카드는 원고 문단을 정확히 찾아 바꾸는 {find, repl}을 들고 있다 — find는 수정본에 **딱 한 번** 나오는 문단(여러 문단이면 빈 줄로 이은 연속 블록)이어야 하고, 만들 때 개수를 검사한다. 떨어진 여러 곳은 카드를 나눈다. 삭제는 빈 줄이 남지 않게 블록째.
- 고르면 원고 탭 내용이 바뀌고 db `choices/<회차-차수>`에 기록된다.
- 카드마다 **작가 메모** 칸과 **새 선택지**(작가가 원본·A·B를 불러와 고쳐 쓰거나 붙여 넣음 → '작가 N' 선택지로 저장, 고르면 원고에 들어감)가 있다 → db `cardx/<회차-차수>` {notes, custom}. 매 턴 choices와 함께 읽고, 메모마다 답한다(2026-11-10 작가).
- 카드 상단 요약: 반영 확인(지난 카드), 바로 고친 것(맞춤법·띄어쓰기 등), 뺀 Codex 지적과 이유.

**매 턴 동기화**
- 작가 저장본(db `drafts/ep<N>`)과 PC 수정본 git diff를 둘 다 보고 **더 최근 것**(savedAt vs 파일 수정 시각)을 기준으로.
- 커밋할 때마다 db `drafts/ep<N>`을 커밋한 판으로 덮어쓴다(읽은 version으로 if_version 고정). 안 맞추면 작가가 옛 판에서 고쳐 자기 수정이 되돌아간다.
- 카드를 다시 만들면 그 회차 검토 탭이 통째로 바뀌므로, 아직 안 고른 카드는 새 판에도 같이 넣는다.

**도구**: `python -m tools.mobile_page` (2026-10-31부터 공용). 작품 폴더 `_mobile/`에 설정(`page.json`)·카드(`cards/epN.py`)·결정 카드(`decisions.py`)·되돌림 기록(`fixes/`)을 두고 `build`로 페이지 전체를 다시 만든다.
- `init --title … --doc 설정집.md` → `build [--current e1|r1|dec]` → '!! db 동기화'로 나온 회차는 `ArtifactData set drafts/epN ← _mobile/db_sync/epN.json`(if_version) → Artifact 게시(`page.json`의 url).
- 카드 파일: `one(번호, 제목, 위치, 원본, [opt('A: 〔설정〕 …', 추천여부, 원본, 제안), …], 설명)`, `B('문단 첫머리')`로 원고 문단 찾기, `lst(제목, [줄…])`를 `EXTRA`에. 변수 `TITLE`, `SUB`, `cards`.
- 회차 탭 추가·다른 판: `ep 0v2 --file '프롤로그 v2.txt' --label '프롤로그 v2'`. 바로 고친 것: `guard add N 옛 새 이유` / 매 턴 `guard check N [파일|db json]`.
