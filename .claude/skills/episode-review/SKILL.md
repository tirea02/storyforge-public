# 회차 검토

인자: 원고 경로. 경로가 없으면 작품(`novels/` 아래 이름)과 회차를 묻거나, 작품이 하나뿐이면 그 작품의 `storyforge.json`에서 가장 최근 회차를 쓴다. 이하 `<작품>` = 원고가 속한 작품 폴더.

## 순서
0. `defaults/작가_작업규칙.md`(공통 작업 규칙)를 따른다. 작품 README '검토 규칙'이 우선.
1. **작품 규칙 읽기**: `<작품>/README.md`(상태 태그 정의, **'## 검토 규칙'** 절), `<작품>/style_profile.md`의 0번(요약)과 2번(피할 것).
2. **기계 점검**: `.venv/Scripts/python -m tools.check_episode <원고>` — 분량(플랫폼 환산), 서식, 대사 기호 짝, 문단 호흡, 짧은 단문 몰림(구간 수·비율 기록, 작품 limit 초과 시 경고), AI 패턴(공통+작품), 띄어쓰기 의심.
   - **작가 저장본을 받으면 매번**: ① 직전 커밋과 비교해 Claude가 고친 곳이 되돌아갔는지(편집기 옛 사본) 확인하고, 되돌아갔으면 바로 작가에게 알린다. ② '작가 메모·괄호' 0건(괄호·줄 끝 'or' = 작가 메모 → 지우고 카드로 답함). ③ '따옴표 모양' 0건(작가가 친 둥근 따옴표 “” ‘’는 작품 표기로 고침). 고친 뒤 다시 돌려 0건인지 확인한다.
3. **기억 묶음**: `.venv/Scripts/python -m tools.recall --from-file <원고> --recent 20` — 이 원고에 나오는 인물·사물의 기록과 직전 회차 마지막 장면.
4. 원고 전체를 읽고 검토한다. 기준:
   - 기억 묶음의 [원고 확정]/[설정 확정]과 충돌하는가. [인물의 추측]·⚠초안을 사실처럼 썼는가.
   - 직전 회차와 시간·장소·상황이 이어지는가. 이전 회차와 같은 문답·같은 마무리를 반복하는가.
   - 작품 README '검토 규칙'의 제약을 어겼는가.
   - AI 습관: 도구가 잡은 것 + 도구가 못 잡는 것(대사 뒤 해설, 같은 판단 반복, 보고서 말투, 설명 과다).
4-1. **역방향 점검(최종 단계 — 매 검토마다 하지 않음)**: Claude·Codex 검토가 다 끝나고 작가가 최종본이라고 할 때(확정 직전) 한 번, 또는 작가가 따로 요청할 때 실행한다(2026-10-28 작가). **자동 포함**: Claude가 원고를 합치거나(여러 판 병합), 새 샘플을 쓰거나, 장면 이상을 크게 다시 쓰거나 새로 쓸 때는 요청이 없어도 그 결과물에 바로 실행하고 보고에 붙인다. 원고에서 **사실처럼 쓰인 주장**을 뽑는다 — 마법·도구의 작동 방식, 인물이 아는 것·할 줄 아는 것, 장소·구역 규칙, 누가 언제 무엇을 했나, 호칭·말투, 수치·기간. 주장마다 키워드로 앞 회차 **원고 원문**(`NN화_수정.txt`)과 설정 문서를 grep해 **해당 부분만** 읽고 대조한다(요약·기억 문서만 보고 판단하지 않는다 — 요약은 어디를 볼지 알려 주는 목차). 문서 표현이 애매하면 원문 장면으로 판단한다(예: '숨으로 메움'이 새길 때인지 켤 때인지). 어긋나면 카드, 원문에 근거가 없으면 '새 설정 [작가 확인]'으로 표시. 보고에 **주장 → 대조한 회차·줄** 표를 짧게 붙인다(한 화 5~15개). **1차는 Codex에 맡긴다**: `.venv/Scripts/python -m tools.codex_worker --project <작품> 사실확인 <회차>`(뒤에서 실행) → `codex/결과/NN화_사실확인.md`의 '근거 자동 대조'에서 '원문에 없음'은 버리고, '어긋남'·'근거 못 찾음'만 Claude가 원문을 열어 판단한다. 초안을 확정본에 맞출 때는 `대조` 작업.
5. (요청 시 또는 작가가 켜 둔 경우) **교차 검토**: `.venv/Scripts/python -m tools.codex_worker --project <작품> 교차검토 <회차>`(작업노트로 거절한 지적 반복 방지) 또는 기존 `tools.second_opinion <원고>` → `<작품>/reviews/`의 Codex 지적에 수용/반박/보류를 달아 `<원고>_claude.md`로 저장 → 반박이 있으면 `--rebuttal`로 2라운드. 최대 2라운드. Codex 답 끝의 `읽은 파일:`에 프롬프트의 필수 파일이 빠졌으면 판정 기록에 적는다.
6. 보고 형식:
   - **좋은 점**(작가 문체가 살아 있는 곳)을 먼저 짧게.
   - **꼭 고칠 것** / **다듬으면 좋은 것**(표: 행, 현재, 문제, 제안) / **그대로 둬도 되는 것**.
   - 교차 검토를 했다면 ① 둘 다 동의 ② 이견(양쪽 근거) ③ 작가 판단 필요로 나눠서.
   - 새로 생긴 설정 후보(확정하면 기록할 것). 분량은 플랫폼 환산 추정치로.

7. 작가 확인 항목은 `<작품>/reviews/<회차>_작가_체크리스트.md`로 저장하고(`- [ ]` 체크박스) `tools.dashboard`로 대시보드를 갱신한다.

## 마무리
- `작업_로그.md`에 이번 작업 요약(한 일 / 작가 확인 필요 / 참고)을 추가 → `tools.dashboard` 갱신 → 작품 폴더 git 커밋.

## 원칙
- 수정을 반영할 때는 `NN화_수정.txt`를 직접 고친다(사본 금지). 교차 검토 기록의 행 번호는 검토 시점 판 기준이므로, 반영 전에 작품 저장소에 커밋해 두면 그 판을 다시 볼 수 있다.
- 작가가 직접 퇴고한 원고를 고쳐 쓰지 않는다. 제안만 한다. 파일 수정은 작가가 요청할 때만.
- 개그 타이밍과 캐릭터 말투를 매끈하게 '정제'하지 않는다.
- 제안 문장 자체에 AI 습관(셋 나열, 펀치 공식)이 들어가지 않았는지 스스로 확인한다.
