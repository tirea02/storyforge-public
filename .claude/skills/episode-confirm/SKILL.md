# 회차 확정과 기억 갱신

장기 연재에서 기억 검색이 제대로 작동하려면 **매 화 확정 때 이 단계를 빠뜨리지 않는 것**이 가장 중요하다.
`<작품>` = 확정본이 속한 작품 폴더. 문서 이름은 작품의 `storyforge.json`의 `memory_files`와 `entities`를 따른다(아래는 기본 이름).
**한 사실은 한 문서에만**(공통 규칙 §8-1, 작품 README의 담당 표): 각 사실은 담당 문서 하나에 적고, 다른 문서엔 링크·한 줄 요약만. 같은 내용을 여러 문서에 덧붙이지 않는다.

## 순서
0. `defaults/작가_작업규칙.md`(공통 작업 규칙)를 따른다. 작품 README '검토 규칙'이 우선.
1. **확정본 = 수정본 파일**(`NN화_수정.txt`). 새 사본을 만들지 않는다. 명백한 누락(따옴표 등)만 작가에게 알리고 고친다. 업로드용 서식 정리가 필요하면 `tools.clean_text`로 `_업로드용` 사본(생성물, git 제외).
2. **점검**: `tools.check_episode`로 서식 문제 0건 확인, 분량(플랫폼 환산) 기록. 작가가 플랫폼 실측 글자 수를 알려 주면 `storyforge.json`의 환산 비율을 보정하고 근거를 `_notes`에 남긴다.
3. **storyforge.json**: 해당 회차의 `file`, `title`, `status: "원고 확정"` 갱신.
4. **회차 기록**(`회차별_기록.md`): 새 절. 상태·분량, 시점, 사건, 새로 확정된 사실, [인물의 추측], 복선, 후속 주의.
5. **설정집**: 새로 확정된 설정만 `[원고 확정: N화]`로 추가. 추측은 [인물의 추측].
6. **memory/open_loops.md**: 새 복선 추가, 기존 복선의 '최근 진전'·'상태' 갱신. 상태 칸은 넷(열림·진행·보류·회수)만 — 메모는 '회수 방향' 칸에. 진전이 생기면 열림 → 진행, 회수되면 진전 칸을 최근 둘만 남기고 줄인다.
7. **memory/timeline.md**: 한 줄 추가.
8. **memory/entities.json**: 새 인물·사물 추가, 새 별칭(이름이 생기면 반드시) 추가. 요약은 짧게 고쳐 쓴다 — 개인 문서가 있는 인물은 인물 현황의 '고정 + 지금'과 같게(회차별 이력을 쌓지 않음). ⚠초안 표시를 확정으로.
8-2. **개인 문서**(작품 폴더 `characters/`, 있으면 — 행적의 담당 문서): 이번 화에 나온 인물의 '행적' 회차표에 한 줄(인용은 원문 그대로), 바뀐 능력·관계·비밀은 고쳐 쓰고 머리말 '기준: N화'를 올린다. 새로 자주 나오는 인물이 생기면 개인 문서를 만들고 `memory_files`에 넣는다.
8-3. **설정 대장**(예: 마법 체계 문서 `설정_마법.md`, `storyforge.json`의 `agents_extra`): 이번 화에 나온 관련 설정을 [원고 확정: N화]로 옮기고, 새로 정해진 것을 적는다.
8-1. **인물 현황**(`storyforge.json`의 `characters`, 있으면): 주요 인물마다 **'지금(N화)' 줄을 고쳐 쓴다 — 회차별 줄을 덧붙이지 않는다**(행적은 8-2 개인 문서에만). 비밀 표에 새 비밀 줄, 말투·집필 주의·다음에 확인할 것 갱신, 머리말 '기준: N화'. 개인 문서가 없는 조연·아이들은 이 문서의 절에 짧게. **작품에 모바일 검토 페이지(장 페이지)가 있으면 인물 현황 탭을 다시 그려 같은 URL로 게시한다**(장이 바뀌어도 탭은 항상 둔다).
9. **설정 검증 목록**: 해결 항목 체크, 새 질문 추가.
10. **Codex 지침 갱신**: `.venv/Scripts/python -m tools.sync_agents --project <작품>` — 위에서 바뀐 기억·결정이 작품 폴더의 `AGENTS.md`(Codex가 자동으로 읽는 요약본)에 반영된다. 작가 결정이 바뀌었으면 `HANDOFF.md` §2~4도 먼저 갱신.
11. **대시보드 갱신**: `.venv/Scripts/python -m tools.dashboard` (작가가 브라우저로 보는 현황판).
11-1. **기억 점검(Dreaming 가벼운 판)**: `.venv/Scripts/python -m tools.memory_audit --project <작품> -o <작품>/reviews/기억점검/<날짜>_NN화.md` → '낡은 표시'는 0건이어야 한다(있으면 바로 고침). 이번에 고친 문서에서 새로 생긴 '근거 없음'(원문과 다른 인용)은 원문대로 고친다. 그 밖에 판단이 필요한 것(설정 충돌, 담당 문서끼리 어긋남)은 고치지 않고 카드로 올린다. 장이 끝나면 `memory-dream` 스킬로 전체 점검.
12. **git 커밋**: 작품 폴더에서 `git add -A && git commit -m "docs: N화 확정 — 기억 문서 갱신"`(작품 저장소) → `git push`(GitHub 비공개 백업).
13. 작가에게 바뀐 파일과 **작가 확인이 필요한 결정**을 짧게 보고.

## 마무리
- `작업_로그.md`에 이번 작업 요약(한 일 / 작가 확인 필요 / 참고)을 추가 → `tools.dashboard` 갱신 → 작품 폴더 git 커밋.

## 원칙
- 원고에 없는 것을 사실로 기록하지 않는다. 작가가 말로 정한 것은 [설정 확정].
- 대사 속 주장(인물의 추측, 소문, AI 조력자의 가설 등)은 [인물의 추측].
- 초안 회차(⚠)에서 나온 내용은 확정 전까지 ⚠ 표시를 유지한다. ⚠는 '초안 출처' 표시로만 쓴다(주의 표시는 '주의:').
- 따옴표 안은 원문 그대로. 줄이면 `…`, 바꿔 말하면 따옴표를 뺀다.
